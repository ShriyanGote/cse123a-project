\subsection{Web Application}

The web application serves as the account-management and onboarding companion to the mobile app. 
It is built using React and deployed on a cloud platform, while being backed by a managed relational database. 
Sensor readings, group membership, device records, and authentication data are all managed within the backend infrastructure, 
which is shared between the web and mobile applications. The interface is organized into two side-by-side panels: 
an \textbf{Account} panel (the Settings page) and a \textbf{Setup guide} panel (the Guide page). The web app exists to let users manage the 
account that the mobile app signs in with, review the devices and groups associated with that account, and consult the first-time setup instructions.

\subsubsection{System Architecture}
The deployed architecture has three coordinated layers:

\begin{itemize}
    \item \textbf{Frontend:} Renders the Settings panel and the Guide panel.
    \item \textbf{Backend Server:} Hosts the sensor-ingestion service used by the microcontroller and authenticated REST services used by both the web app and the mobile app to read and update account, group, and device data.
    \item \textbf{Database:} Provides authentication, a Postgres database for groups/devices/readings, and row-level-security enforcement.
\end{itemize}

\subsubsection{Settings Page}
The Settings page is the Account panel of the web app. It serves two states depending on whether the user is signed in.

\paragraph{Signed out.}
The panel renders a Sign-In form with email and password fields. A hint reminds the user to sign in with the same account they use in the mobile app, since the two clients share the same database authentication system.

\paragraph{Signed in.}
After authentication, the panel displays:
\begin{itemize}
    \item The signed-in user's email and a sign-out control.
    \item \textbf{My Groups} --- a list of the groups the user belongs to, including the user's role in each group and the associated device ID where applicable. Group and device data are fetched from the authenticated REST services.
    \item \textbf{My Devices} --- a list of devices owned by the user, showing each device's name and status.
    \item \textbf{Security} --- a button to sign out of all devices currently signed in to the account and a button to delete the account. Deleting the account will revoke all devices and groups associated with the account.
\end{itemize}

\noindent All requests from the Settings page attach the database access token as a Bearer token; the REST services validate the token before returning data scoped to the user.

\subsubsection{Setup Guide Page}
The Guide page is a static, step-by-step walkthrough for first-time setup of a Smart Base. It is intended to be readable on a desktop screen while the user follows along with the mobile app. The guide covers:

\begin{enumerate}
    \item Unboxing and powering on the base.
    \item Installing the mobile app.
    \item Signing in (or creating an account) and granting Bluetooth and Camera permissions.
    \item Opening the Provision Device flow from the mobile dashboard.
    \item Scanning the QR sticker on the base, which auto-fills the device name and ID.
    \item Entering the Wi-Fi SSID and password the base should join.
    \item Sending the authentication token and Wi-Fi credentials to the base over Bluetooth Low Energy.
    \item Waiting for the base to confirm Wi-Fi connectivity and begin reporting readings.
\end{enumerate}

\noindent The Guide page deliberately mirrors the mobile-app provisioning flow so users have a reference while completing setup on their phone.

\subsubsection{REST API}
The backend server exposes a small REST API shared by the web app, the mobile app, and the microcontroller. User-facing requests carry the database access token as a Bearer credential; sensor uploads use a per-device credential established during provisioning.

\begin{itemize}
    \item \textbf{Authentication} --- Handles email/password sign-in, sign-up, and email verification, and issues access tokens for authenticated sessions. The web Settings sign-in form and the mobile Auth screen obtain tokens through the shared database authentication service; all other user-facing REST endpoints require a valid Bearer token before returning account, group, or device data.
    \item \textbf{Account and profile} --- Read the signed-in user's profile, update display name, sign out all active sessions, and permanently delete the account. Used by the Settings page Security actions.
    \item \textbf{App state} --- Returns aggregated state the clients need on load, including recent reading context for the signed-in user. Used by the Settings page and the Guide page. 
    \item \textbf{Device registry} --- List devices owned by the user and register a new device during mobile BLE provisioning (hardware identity plus one-time credential). Listing is used by the Settings page and mobile dashboard; registration is used by the mobile provisioning flow.
    \item \textbf{Group membership} --- List the user's groups, create a new group, join an existing group by invite code, and fetch detailed group data including members and the latest reading. Listing is used by the Settings page and mobile dashboard; create, join, and detail are used primarily by the mobile app.
    \item \textbf{Group management} --- Rename or delete a group, transfer ownership, and update member roles or remove members. Used by the mobile app.
    \item \textbf{Group calibration} --- Set empty and full reference weights for a group's associated device. Used by the mobile Group screen.
    \item \textbf{Sensor ingestion} --- Accept weight readings from the microcontroller over HTTPS, store them, derive water level from calibration data, and optionally trigger low-water push notifications. Used by the Smart Base firmware.
\end{itemize}

\subsubsection{Data Model}
The shared database stores the entities both clients rely on:

\begin{itemize}
    \item \textbf{Devices} --- Registered bases tied to a user account, including identity, display name, and provisioning credentials where applicable. Shown on the Settings page under My Devices and on the mobile app dashboard.
    \item \textbf{Groups and membership} --- Shared groups with invite codes, role-based membership, associated devices, and per-group calibration values. Shown on the Settings page under My Groups and on the mobile app dashboard.
    \item \textbf{User profiles} --- One record per user, including display name and authentication linkage. Used by both the web app and mobile app.
    \item \textbf{Water readings} --- Timestamped weight readings uploaded by the microcontroller. Consumed by the mobile app to show live water level.
\end{itemize}
