\subsection{Web Application}

The web application is the user-facing interface for the smart water-level monitor. 
In the current implementation, the system is fully deployed as a React frontend on Vercel with API endpoints and a 
Supabase backend. The design goal is to provide a clear real-time estimate of remaining water in the container, 
allow user calibration for different pitcher sizes, and send refill notifications when the water level becomes low.

\subsubsection{Current Design}

\textbf{System Architecture}
\vspace{0.3em}

\noindent The deployed architecture has three coordinated layers:

\begin{itemize}
	\item \textbf{Frontend dashboard (React):} Displays the latest reading, computes estimated level percentage, and status indicators.
    \item \textbf{Vercel backend:} Receives sensor uploads and notification subscriptions.
	\item \textbf{Supabase Storage:} Stores water readings, calibration parameters, and browser push subscription tokens.
\end{itemize}

\noindent Sensor data is sent to the backend endpoint with an API key, validated, and inserted into persistent storage. 
The dashboard reads the newest value from Supabase on a polling interval and renders the latest state.\\

\noindent\textbf{Frontend Design and User Experience}
\vspace{0.3em}

\noindent The current dashboard is intentionally minimal and task-focused. Core interface elements are:

\begin{itemize}
	\item A large water-level visualization (pitcher graphic with animated fill height).
	\item A numerical percentage readout for quick interpretation.
	\item A water-present/empty status indicator.
	\item Metadata showing last update timestamp, measured weight, and battery voltage (when available).
\end{itemize}

\noindent Users can quickly assess whether refill action is needed without interpreting raw sensor values.
